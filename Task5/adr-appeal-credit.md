## ADR: Подача заявки на кредит онлайн

### Название задачи:
ADR: Архитектура подачи кредитной заявки онлайн через сайт и интернет-банк

### Автор:
Архитектор команды цифровой трансформации

### Дата:
2026-06-12

### Функциональные требования

| № | Действующие лица или системы | Use Case | Описание |
|---|------------------------------|----------|----------|
| 1 | Потенциальный клиент, Сайт | Просмотр предложения по кредиту | Клиент на сайте видит общие условия кредита, полная информация хранится в Кредитном конвейере |
| 2 | Потенциальный клиент, Сайт | Подача заявки с контактными данными | Клиент оставляет ФИО и телефон. Заявка передаётся в Кредитный конвейер, клиенту приходит СМС о необходимости посетить отделение |
| 3 | Потенциальный клиент, Сайт | Подача заявки с паспортными данными | Клиент заполняет ФИО, телефон и паспортные данные. Система скоринга оценивает клиента через БКИ и сразу выдаёт предварительное решение |
| 4 | Клиент банка, Интернет-банк | Просмотр доступных кредитов и предодобренного предложения | Клиент видит список кредитов с условиями. Если по клиенту ранее выполнялся скоринг, выводится предодобренное предложение с суммой |
| 5 | Клиент банка, Интернет-банк | Подача заявки на кредит | Клиент выбирает счёт зачисления, заполняет данные, подтверждает СМС-кодом. Для предодобренных — упрощённая процедура скоринга |
| 6 | Клиент банка, Интернет-банк | Подача заявки по предодобренному предложению | Повторный скоринг по упрощённой процедуре. Заявка обрабатывается в течение одного рабочего дня |
| 7 | Система кредитного скоринга | Скоринг клиента по данным БКИ | Для новых клиентов — только общие данные БКИ. Для существующих — данные из АБС + БКИ |
| 8 | Кредитный конвейер | Маршрутизация заявок | Приём заявок с сайта и интернет-банка онлайн, обработка сотрудниками. Предодобренные заявки — приоритетная очередь |
| 9 | Сотрудник отделения, АБС | Работа с заявкой клиента | Если клиент уже подал заявку на сайте, сотрудник продолжает работу с той же заявкой, не создавая новую |
| 10 | Клиент, СМС-шлюз | Информирование о статусе заявки | СМС-уведомления: подтверждение подачи, изменение статуса, приглашение в отделение |

### Нефункциональные требования

| № | Требование |
|---|------------|
| 1 | Шифрование трафика (HTTPS/TLS) при передаче паспортных и контактных данных |
| 2 | Предодобренные заявки должны обрабатываться в течение одного рабочего дня |
| 3 | Кредитный конвейер должен принимать заявки онлайн, а не раз в сутки через АБС |
| 4 | Система скоринга не должна нагружаться дополнительными процессами по предрасчётам в пиковые часы |
| 5 | Кредитный конвейер и система скоринга поддерживают горизонтальное масштабирование и работу 24/7 |
| 6 | Избегать прямой работы интернет-банка с API АБС |
| 7 | Использовать существующие технологии: Camunda (Кредитный конвейер), Python Flask (скоринг), Java Spring Boot |
| 8 | Предодобренный скоринг для существующих клиентов рассчитывается заранее, не в момент запроса |
| 9 | Заявки с сайта и интернет-банка попадают в Кредитный конвейер минуя АБС |
| 10 | Сохранение данных заявки при сбое — клиент не должен повторно подавать заявку в отделении |

### Решение

**Логика принятия решений:**

1. **Заявки с сайта и интернет-банка — напрямую в Кредитный конвейер, минуя АБС.** Сейчас заявки попадают в конвейер раз в сутки через АБС, что недопустимо для онлайн-процесса. Кредитный конвейер (Camunda) должен принимать заявки через REST API. Это решает проблему скорости и разгружает АБС.

2. **Предодобренные предложения рассчитываются заранее.** Система скоринга в непиковые часы (ночью) производит предрасчёт для существующих клиентов и сохраняет результаты в Кредитный конвейер. При заходе клиента в интернет-банк предложение уже готово, дополнительной нагрузки на скоринг нет.

3. **Для новых клиентов с сайта — два сценария скоринга:**
   - Только ФИО и телефон — заявка без скоринга, клиент получает СМС о визите в отделение
   - С паспортными данными — онлайн-скоринг через БКИ, немедленное предварительное решение

4. **Интернет-банк не обращается к АБС напрямую.** Данные клиента (счета, история) для предодобренного предложения берутся из внутренней БД интернет-банка и Кредитного конвейера. Скоринг работает с БКИ и собственными данными из АБС, выгруженными заранее.

5. **Credit Application Gateway — новый микросервис.** Принимает заявки от сайта и интернет-банка, валидирует, маршрутизирует в Кредитный конвейер. Реализован на Java Spring Boot (экспертиза есть в командах АБС и кол-центра). Позволяет не менять ядро интернет-банка (монолит на ASP.NET MVC).

6. **Кредитный конвейер дорабатывается силами IT-отдела банка.** Camunda позволяет менять обработчики бизнес-процессов на Java. Добавляются два новых процесса: приоритетная обработка предодобренных заявок и обработка заявок с сайта.

### Альтернативы

1. **Передача заявок через АБС, как сейчас.**
   - Отвергнуто: заявки попадают в конвейер раз в сутки, ускорить обмен невозможно. Требование бизнеса — решение в течение одного дня для предодобренных заявок.

2. **Прямая интеграция интернет-банка с Кредитным конвейером без Credit Application Gateway.**
   - Отвергнуто: ядро интернет-банка обновляется подрядчиком, изменения дороги и медленны. Gateway позволяет вести разработку силами банка независимо.

3. **Онлайн-скоринг для всех заявок, включая предодобренные.**
   - Частично отвергнуто: система скоринга испытывает повышенную нагрузку в рабочие часы. Предодобренные предложения рассчитываются заранее ночью. При подаче заявки — упрощённая проверка, а не полный пересчёт.

4. **Хранение предодобренных предложений в интернет-банке.**
   - Отвергнуто: лучше хранить в Кредитном конвейере как мастер-системе по кредитным заявкам. Интернет-банк только отображает данные, полученные через Gateway.

**Недостатки, ограничения, риски**

- **Credit Application Gateway — новый микросервис**, требует разработки и поддержки. Но он изолирует изменения от монолита интернет-банка и АБС.
- **Предрасчёт скоринга ночью** — если ставки или условия изменились днём, предодобренное предложение может быть неактуальным. При подаче заявки всё равно выполняется упрощённая проверка.
- **Зависимость от БКИ** — для новых клиентов доступны только общие данные БКИ, точность скоринга ниже, чем для существующих клиентов.
- **Идентификация клиента** — для получения кредита всё равно нужен визит в отделение, онлайн-процесс ограничен подачей заявки и предварительным решением.
- **Кредитный конвейер на Camunda** — в банке есть специалисты, которые могут менять обработчики, но сложные изменения могут потребовать привлечения подрядчика, внедрявшего систему.
